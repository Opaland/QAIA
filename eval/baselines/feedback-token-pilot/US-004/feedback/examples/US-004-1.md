# US-004-1 — unresolved FX rate should not hard-refuse submission

**Scenario**: `@QAIA-US-004-025` (`.qaia/testbooks/US-004/approval-chain.feature`, AC6-C2)

**Generated (as produced by `testbook-generate`)**:

```gherkin
Scenario: Submitting in a currency with no resolvable rate is refused
  Given "employee@demo" has a draft report in "CHF" with one line "hotel" of 100.00 dated 2026-07-21, receipt attached
  When "employee@demo" submits the report
  Then the attempt is refused with a 422 status
```

This scenario resolved the open question **Q4** (rate source undefined) with the default
recorded in `.qaia/state/US-004/02-understanding.md`: "no resolvable rate for an unsupported
currency is refused at submission."

**What was wrong (tester correction, Finance SME review)**: a hard 422 refusal blocks the
employee from submitting at all — the report and its receipts are lost from the workflow, and
the employee has to re-enter everything once the rate is available. Actual Finance policy: an
unresolvable currency is **accepted** into a `pending-rate` sub-status (not `submitted` in the
normal chain), the report is held out of the approval queue, and Finance is notified to resolve
the rate manually. Once resolved, the report re-enters `submitted` at its correct converted
total. No data entered by the employee is lost, and no report silently disappears from an
audit-trail perspective (AC8's completeness promise).

**Corrected form**:

```gherkin
Scenario: Submitting in a currency with no resolvable rate is held for manual rate resolution
  Given "employee@demo" has a draft report in "CHF" with one line "hotel" of 100.00 dated 2026-07-21, receipt attached
  When "employee@demo" submits the report
  Then report "R" status is "pending-rate"
  And the report does not enter any approver's queue
  And "finance@demo" is notified to resolve the missing rate
```

**Why**: this is a domain rule, not a one-off wording tweak — it changes the *outcome* class
(new status `pending-rate` vs. an outright refusal) and it recurs with the same shape for stale
rates (see `US-004-2`). Filed as `business-rule` — candidate for `knowledge/` once a second
instance of the same underlying policy is captured (D22 promotion threshold, ≥ 2 examples).

**Provenance**: simulated correction, non-interactive pilot run (2026-07-25) — no live Finance
SME available in this session; the correction is a plausible, realistic domain rule invented
for measurement purposes, arbitrated `simulated: accepted` per `skills/README.md` rule 3, not a
literal recorded conversation.
