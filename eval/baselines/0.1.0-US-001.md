## Convergent findings → fixes applied to skills (0.1.0 → 0.1.1)

From the judges (all three converge):
1. **Cross-AC ambiguity misses** (dim 6): the planted AC2×AC6 interaction (slot freed by cancellation vs 2h booking window) was missed or only partially caught in all runs → `need-understanding` now mandates a cross-AC interaction pass and a "which clock/referential?" check on every duration.
2. **Priorities without rationale in the deliverable** (dim 9, capped at 1 in all runs): rationale lived only in internal state files → `prioritize` and the matrix contract now require a one-line risk driver per assignment inside the delivered book.
3. **Use-case scenario breaks atomicity** (dim 1, runs 1 & 3): → `istqb-design`/`testbook-generate` now constrain journey scenarios (single journey-level outcome, tagged `@smoke`, excluded from atomicity accounting).

From the generator runs (all three converge):
4. **D20 ratio ambiguously defined** between skills → single definition: numerator = scenarios tagged `@negative`; denominator = all generated scenario blocks (Outline = 1 block); boundary coverage reported separately.
5. **No rule for generating on `[open]` items** → explicit rule: generate with the proposed safe default, tag `@low-confidence`, cite the question ID inline; never silently resolve.
6. **References to artifacts the nominal path never creates** (`knowledge/`, synthesis contract living in `testbook-export`) → degraded-mode rules added to the shared contract; the synthesis/review-aid contract moved to the shared contract.
7. **Mixed-priority Scenario Outlines** unusable → merge rule: same priority and confidence only.
8. Secondary: duplicate-scan scope defined; one-`When`-per-scenario lint rule; artifacts now carry resume frontmatter (BMAD A1).

Deviation log: runs were non-interactive (7 validation points simulated per run) — the conversational validation path is NOT covered by this baseline and must be exercised by the pilots (gate G2).
