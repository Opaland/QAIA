# US-EVAL-009-001 — two P1 scenarios assert unconfirmed proposed defaults

- **Scenario IDs**: `@QAIA-US-EVAL-009-007` (AC3-C4), `@QAIA-US-EVAL-009-008` (AC3-C5)
- **Classification**: `one-off`
- **What was wrong**: both scenarios are tagged `@P1` and assert a concrete outcome
  ("the 'Proceed to Checkout' action is available" / "the attempt is refused") whose truth value
  is `[open]` in `state/02-understanding.md` (Q3, Q7). Each could turn out to be the *opposite* of
  the target's real behaviour.
- **Corrected form (proposed, not applied)**: keep the scenarios but hold them out of the
  automated set until Q3 and Q7 are arbitrated by a human — or split each into the two candidate
  outcomes behind an explicit `@pending-arbitration` tag, so a green run cannot be read as
  confirmation of an unconfirmed policy.
- **Why**: a P1 scenario asserting an unconfirmed default is the "converged, confident, wrong"
  failure mode: it goes green against whichever behaviour the system happens to have and stops
  looking like a question. Q7 in particular is an access boundary, not a nuance.
